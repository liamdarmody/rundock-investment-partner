# What changed from the original, and why

The original is the Investment Partner Hub reference plugin on the `plugin-framework-phase-6-investment-dashboard` branch (`895299a`), under `test/fixtures/investment-dashboard/`, and the dashboard in the issue's reference image. It targets a plugin framework that did not ship. This package targets what Rundock ships in 0.15.0: the extension contract (`docs/EXTENSION-HOST.md`), Rundock UI (`docs/RUNDOCK-UI.md`), package starter files (`docs/PACKAGES.md`), and two additions made for exactly this dashboard, named sources and ask. Each change below names the rule that required it.

What survived from the original: the three agents' roles and review sequence, the portfolio math (market value, totals, grouping, the stale-price rule), the data shapes inside each document (extended, never renamed), the decision journal's five statuses, and the layout of the reference image, section by section.

## The package

**1. `manifest.json` became `rundock.json`.** Rundock reads exactly one manifest, `rundock.json`, with a lowercase slug `name`, a `version`, and an `extension` block. `id`, the display name, `description`, `author`, `schemaVersion` and `rundock.minimumVersion` are not read, so they are gone rather than left to look meaningful. This is the package's first public release, 1.0.0. The data inside it has its own version, `schemaVersion` 2 (see 7), because its shape changed from the original.

**2. `ui` became an `extension` block with a claim and four declarations.** An extension must claim what it draws. This one claims `*.md` narrowed by the marker `investment-partner`, so it draws only notes that carry it. It declares `writes` (it may change the notes it draws), `sources` (a dashboard note may hand it other notes; see 9), `asks: ["lead-partner"]` (see 14) and `rundockUi: "1.0"` (the component library version it was built against). The install card states each one to the person before anything is written.

**3. `agents` and `skills` left the manifest.** Rundock finds agents at `.claude/agents/<slug>.md` and skills at `.claude/skills/<slug>/SKILL.md` by convention, so they live there and arrive as the person's own files, with no reserved names and no ownership guards. `reportsTo: "$orchestrator"` became no `reportsTo` at all, which already means "under whoever leads the workspace". Each agent carries an `order` (10 for Lead Partner, 10.1 and 10.2 for the two under it): Rundock puts an agent on the team only when it has one, and only an agent on the team receives its skills or can be asked from a view.

## Where the data lives

**4. `resources` in `.rundock/plugin-data/` became notes in `Investments/`.** A view is never handed a file in a hidden folder, and uninstalling an extension removes what the extension owns, which under the original layout would have deleted someone's portfolio. As ordinary notes, the data belongs to the person, the agents can read it, and an uninstall leaves it alone.

**5. The JSON files became markdown notes with a marker and a `json` block.** A bare `*.json` match would claim every JSON file in the workspace. The way to claim only some files is a frontmatter marker, and only markdown has frontmatter. So each note carries `investment-partner: portfolio` (or `risk-profile`, `decision-journal`) and keeps your data shape in its first `json` block. Everything outside the block is the person's prose, and a write never touches it.

**6. `templates` became starter files.** A package's `starter/<path>` lands at `<path>` when the person has nothing there, and belongs to them from then on. So the four notes (the three above and the dashboard) arrive with the install, filled with sample data that reproduces the reference image's figures. The earlier setup skill that created them is now Investment Reset, which only puts back a note that has gone missing, as an empty, valid one, and never overwrites.

**7. The schema grew to the reference image, and nothing was renamed.** The image shows five limits, two tax preferences, a strategy regime, geography and account type. The portfolio gains `type` on an account and `geography`, `fund` and `illiquid` on a position. The risk profile gains `maximumAccountFraction`, `maximumIlliquidFraction`, `taxPreferences.avoidShortTermGains` and `strategyRegime`. `schemaVersion` is 2. The two new limits are optional, so a schema 1 note still reads, and a limit it never set is reported as not set rather than compared against a number nobody chose.

**8. Agents may write the data, in two narrow ways.** In the original only the dashboard wrote. The data is now ordinary notes, and the view is only open while someone looks at it, so Lead Partner may add a journal entry as `proposed`, and may update the portfolio when the person states a change. Limits, tax preferences, the regime and the dashboard's list of notes stay the person's to change.

## The dashboard

**9. One route over three resources became one dashboard note that names its sources.** An extension draws a file the person opens, and until now it was handed that one file only, which is why the first port could not compare the portfolio against the limits. Rundock 0.15 adds named sources: a note marked by an extension that declares `sources` lists files under `sources:` as exact paths, and Rundock hands the view exactly those files and nothing else. So `Investments/Investment Dashboard.md` holds no data; it lists the portfolio, risk profile and decision journal, and the view draws them together. The view recognises each source by its marker, not its name, so the notes can be renamed. It never writes the dashboard note itself, and Rundock refuses any write that would change a note's `sources:` list, so a view can never widen what it is given.

**10. A route and a nav rail entry became a note the person pins.** A rail that grows with every install stops being designed. The dashboard is a note; pinning it keeps it one click away.

**11. `RundockPluginHost.register` and the mount context became the frame protocol.** The view runs in a frame with `sandbox="allow-scripts"`, an opaque origin and a `default-src 'none'` policy. It announces `ready`, receives `init` (the note, its sources and the theme) and later `sources` when a source changes on disk, and may send `resize`, `error`, `open`, `change`, `changeSource` and `ask`. There is no `getResource`, `replaceResource`, `subscribe`, `startConversation` or `escapeHtml` on the other side. Every message name lives in one adapter in `ui/index.js`, so if a name moves, that is the one place to change.

**12. `replaceResource` with an etag and a Save button became autosave.** `changeSource` carries one source's whole new text and the path the note listed; `change` does the same for a note opened on its own. Rundock writes once the edits pause, through the same guarded save its editors use, which refuses to overwrite a note changed elsewhere since it was opened. Your conflict discipline survives; the code for it is Rundock's. Rundock reports each write back, and the view recognises its own echo, so a slider is never redrawn under the pointer.

**13. The `plugin-data-changed` subscription became the `sources` message.** When a listed note changes on disk (an agent adding a journal entry, say), Rundock resolves the list again and sends it, and the dashboard redraws from the new text.

**14. "Start Lead Partner conversation" returned, as ask.** A view cannot reach conversations; an agent acts with the person's own access. Rundock 0.15 adds `ask`: after a click inside the view, Rundock opens a new conversation with an agent the manifest declared and puts a message in the box, unsent. The person sends it, changes it, or leaves it, and nothing comes back to the view. The dashboard has two, and only ever shows one Ask Lead Partner: Propose a trade, a small form beneath the stat tiles (ticker, buy or sell, an amount in USD, each checked in place) whose Draft for Lead Partner writes a complete request ("I want to buy $5,000 of MSFT. Check it against my risk limits first, and if it fits, add it to my decision journal as proposed."); and Ask Lead Partner, which sits in the risk alert with the breaches while something is over a limit, and quietly in the header with a summary of where things stand when nothing is. While anything is over a limit, the alert's Ask Lead Partner is the one primary action and Propose a trade steps back to secondary; within limits, Propose a trade is primary. Buy or sell is one line of Rundock UI tabs used as a segmented choice (the pattern Rundock's own mode toggle uses), so the three fields line up. As a secondary button the tile takes a control's edge rather than a card's, so it never reads as an empty stat card, and it stays visibly pressed while the form it opened is showing. Each carries the note paths so Lead Partner reads the notes rather than trusting a quoted figure. The form never sends, never writes the journal and never places anything: an original "trade" in a view that cannot reach a brokerage would only ever have been a draft, so it says so.

**15. The limit comparison is back, and covers all five limits.** With the portfolio and the risk profile both in hand, the dashboard checks every limit and names each breach in a sentence ("BTC is 15.8% of the portfolio, above the 8.0% single-position maximum."), in a warning-toned alert as in the reference image. Every percentage on the screen and in every drafted message comes from one formatter, to one decimal. A ticker held in two accounts is one position. A position marked `fund` (an index or bond fund) counts toward neither the single-position nor the sector limit, because it is many positions across many sectors. Exactly at a limit is inside it. The account meters are drawn against the single-account limit, and the cash meter is marked at the minimum reserve. The same rule is written into the review skill, so an agent and the screen never disagree about what is over.

**16. The Agent Debate panel is not built.** Nothing streams to a view: a view is never shown a conversation or its reply. The live panel in the reference image would need exactly that, so it is left out rather than faked.

**17. The chat side panel (`slots`) stays gone.** An extension draws only in the file view. A second panel beside the conversation would be confusing, which is a product call rather than a security one.

## The components

**18. Your markup and stylesheet became Rundock UI.** Rundock injects its component library into every extension frame, so a view's buttons, sliders, toggles, tabs, option lists, meters, alerts, stats, board and menus are Rundock's own and change when Rundock's do. Your `inv-journal-board`, `inv-journal-column` and `inv-journal-card` (a kanban rebuilt because there was no way to reuse Rundock's) became `Rundock.ui.board`. Only the donut and its legend are this package's own drawing, inside a `Rundock.ui.canvas`. `ui/investment.css` now only lays the components out; a test holds it off every control's geometry.

**19. The board moves a card by its menu first.** Every card has a menu button listing the five statuses, so a keyboard or a screen reader moves a decision as easily as a pointer; drag is layered on top. The original changed status through a select per card, so this keeps that path and adds drag.

**20. Every value is set as text.** Rundock UI never parses a label as markup, and the view builds no HTML strings, so a ticker or thesis containing markup shows as text. The view reaches for no network or storage; a test holds the source to that.

**21. Both themes need no code.** Rundock injects the active theme's tokens, and Rundock UI is built on them. The chart slices use Rundock's chart tokens, which hold in both themes.

## Setting up, currency and accounts

**22. Sample data says so, and offers two ways out.** The starter portfolio carries `"sample": true`. While it does, the dashboard shows "This is sample data." with Set up with Lead Partner, which drafts a short interview (country, base currency, the accounts held, whether to import from statements), and Start empty, which clears the portfolio and journal to blank, valid notes in a chosen currency and keeps the risk profile's defaults. Starting empty is never silent: a line says what was cleared, with Undo, which puts both notes back exactly. The first edit clears the flag, because from then on the data is the person's. Investment Reset offers the same empty start, and only ever empties a portfolio that still carries the flag. Rule: a person's own data is never cleared without their say, and sample data is never mistaken for theirs.

**23. One currency per portfolio, in the person's locale.** The original was USD only. `baseCurrency` is now honoured everywhere: every amount is written with `Intl.NumberFormat` in the person's locale (£399,920; 399.920 € in German), the entry fields and their labels say the currency ("Amount (GBP)"), and the messages drafted for Lead Partner carry it. A new or empty portfolio takes its currency from the locale's region. It is changed from a small label beside the total ("£77,240 · GBP ▾") that opens a picker of fifteen common currencies and Other, which takes any three-letter code the runtime knows; the code shows only where the symbol could be several currencies, so never "US$399,920 · USD". While the sample banner is up, its own currency choice is the only currency control on screen. There is no conversion, and the help says so: changing the currency relabels the amounts. Rule: a number the view cannot convert honestly is not converted at all.

**24. Accounts are edited where they are shown.** In Account breakdown, an account's name opens it in place (name, a free-text type with suggestions matched to the currency, and cash), saving as it goes; "+ Add account" adds one; removing one is immediate with Undo, and an account that still holds positions cannot be removed, with the reason beside the disabled button. Rule: a destructive action is undone rather than confirmed, and one that would lose data the person has not moved is not offered.

**25. Positions are added, moved and removed on the dashboard.** The Positions table joins the dashboard, below the Decision board, with one quiet menu per row to move a position to another account or remove it (with Undo), quantity and price editable in place, and, behind "+ Add position", an Add position row (ticker, account, quantity, price, the category fields defaulted and editable, and Fund and Illiquid checkboxes, since the risk check reads both), and Escape to put it away.

**26. Quantity and price read as text, and open in place when selected.** Every quantity and price was a live input, all the time, which made the table slow to read and widened a column whenever one was focused. Positions now uses Rundock UI's editable table: values read as plain numbers in fixed-width columns, and selecting one (a click, a tap, Enter or F2) opens an editor laid over that cell, so nothing moves. Enter or Tab saves it (Tab goes on to the next value), Escape puts it back. The table checks the number, digits with one decimal point and zero or more, and says so under the cell; the view writes it. Ticker, account, market value and priced are read-only, and the row menu keeps only Move and Remove. A currency symbol typed in front of an amount is no longer accepted here, as it still is in Add position.

**27. Every empty panel teaches, and limits speak in one colour.** Over-limit meter bars take the alert's attention tone rather than danger red, so the screen describes a limit breach one way. With no accounts, positions or decisions, each panel says so and says what to do next, including asking Lead Partner to set up from statements.

**28. A change from outside is shown as one.** When Lead Partner writes a note, the dashboard redraws from Rundock's `sources` message as before, and now says "Updated just now, from a change made outside this dashboard." Its own writes never show it.

**29. Positions columns size to their contents, and resize.** Every column is measured once, when the table first draws, and every column keeps that natural width except Account, the main column (`grow: true`), which takes the card's spare room, so the table fills its width with the row menu at the right edge. Account is named rather than left to Rundock UI's default pick, because with short account names Priced, whose widest value is a months-old date, would otherwise be the widest text column and take the room. Each column's header has a resize handle: drag it, or focus it and use the arrow keys, and Enter or a double-click puts the column back. The widths are kept in Rundock's view state for this extension and this note, in Rundock's own folder and never in a note, so they survive a reload and leaving the note and coming back: Rundock UI's table does it with `stateKey: 'positions'`, and the view keeps no widths itself. A width is a view preference, not anybody's data. The widths are per machine, and a renamed note starts without them. On a Rundock without view state, the columns still resize, and the widths last until Positions is next drawn.

## Known gaps

- An edit typed into the portfolio's positions table and not yet written is lost if the note changes on disk in that moment, because Rundock cannot see edits the view holds.
- One currency per portfolio, with no conversion, and prices entered by hand. A holding priced in another currency has to be entered at its price in the portfolio's currency.
- An amount is typed with a full stop as the decimal point, whatever the locale; a German "5.000,25" is not read.
- The dashboard needs a Rundock with named sources and Rundock UI (0.15.0). On a Rundock with Rundock UI but no named sources, the dashboard says so and offers each note to open on its own, and each note draws its own part.
